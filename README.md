# Evil Islands Database Editor

Текущая версия: **0.3.0-preview.3**.

Безопасный редактор `database.res` для «Проклятых Земель» (Evil Islands). Первая версия ориентирована на контролируемое ручное редактирование: исходная база открывается только для чтения, результат создаётся отдельным файлом, а перед использованием повторно разбирается и проверяется.

Интерфейс выполнен в нейтральной тёмной теме, близкой по принципам к современному интерфейсу ChatGPT: спокойный графитовый фон, высокий контраст текста, сдержанные акценты и хорошо различимые состояния ошибок и изменений.

Окно называется **EI Database Studio — Preview**. Основная палитра: `#212121` для рабочей области, `#171717` для навигации, `#2F2F2F` для карточек и зелёный акцент `#10A37F`.

## Главное правило безопасности

Приложение не устанавливает файлы в игру и не перезаписывает открытую базу. Сохранение допускается только в новый файл через «Сохранить как». Копирование готового результата в каталог игры остаётся отдельным ручным действием пользователя.

При сохранении редактор должен соблюдать следующие инварианты:

- канонический путь результата отличается от пути источника;
- уже существующий файл не перезаписывается;
- каталоги игры, `Starter\MODS` и пути через junction/символические ссылки отклоняются;
- неизменённые внутренние ресурсы копируются побайтово;
- созданный RES повторно открывается и проходит структурную проверку;
- источник удерживается открытым только для чтения и повторно сверяется по SHA-256 перед фиксацией результата;
- финальное сохранение является короткой непрерываемой транзакцией: временный файл полностью записывается и проверяется до атомарного переименования;
- ошибки записи или валидации не превращают копию в «успешный» результат.

Для проверки этих правил в репозитории есть автономный консольный проект `EvilIslands.DatabaseEditor.Verification`. Он использует только уникальный каталог внутри `%TEMP%` и никогда не пишет рядом с проверяемой базой или в каталог игры.

## Возможности первой версии

- чтение заголовка и каталога контейнера Nival RES;
- обзор всех внутренних ресурсов с размерами и смещениями;
- структурная проверка границ ресурсов и TLV-чанков внутренних `*db`;
- иерархический каталог восьми внутренних БД и 26 отдельных таблиц, как в классическом DBEditor;
- просмотр всех записей из `items.idb`, `levers.ldb`, `perks.pdb`, `prints.db`, `spells.sdb`, `units.udb`, `acks.db` и `quests.qdb` (3 414 в reference и 3 417 в актуальной JamaisVu135);
- Excel-подобный экран выбранной таблицы: записи расположены по строкам, поля — по столбцам;
- типизированное отображение всех 380 физических полей во всех 26 таблицах: списки, битовые маски и вложенные структуры раскрываются в 578 понятных колонок без raw Hex;
- схемы классического DBEditor встроены в приложение и дополнены подтверждёнными структурами движка для массивов навыков, доспехов, квестовых координат и реплик;
- закреплённые номер и поле имени, горизонтальная прокрутка, сортировка, копирование клеток и режимы «все/основные столбцы»;
- компактные ширины по типу данных, обрезание длинного текста с полной подсказкой и сохранение ручного изменения ширины;
- отдельный поиск по выбранной таблице и подсказки с точным путём поля;
- редактирование поддерживаемых полей прямо в клетках с применением по `Enter` и отменой по `Esc`;
- ручной текстовый ввод ссылок `Base Race` и прототипов трёх таблиц шаблонов магии; неверное значение не подменяется автоматически и обнаруживается семантической проверкой;
- безопасное добавление строки клонированием выбранного образца только в конец разрешённой таблицы: материалы, таблицы юнитов и заклинаний;
- автоматический физический ID нового материала, отдельная операция Undo/Redo и блокировка сохранения, пока технический ключ новой строки пуст/не уникален либо ID материала не равен его позиции;
- явный список изменений и отмена/повтор действий в интерфейсе;
- семантическая проверка вложенной магии оружия и доспехов: совместимость материала, энергия, сложность, наличие `ic`/`it` и runtime-лимит восьми рун;
- строка и клетка с диагностикой подсвечиваются; кнопка «Открыть» и двойной щелчок по сообщению переходят к точной таблице, записи и полю без автоматического изменения данных;
- безопасное сохранение в новый RES с повторным открытием результата;
- закрытие с несохранёнными изменениями показывает отложенное подтверждение и не вызывает WPF-ошибку повторного закрытия окна;
- сохранение неизвестных и не затронутых данных без преобразования.

## Запуск

Для сборки требуются Windows и .NET 9 SDK. Для запуска готового handoff достаточно
Microsoft .NET 9 Desktop Runtime. Внешние NuGet-пакеты проекту не нужны.

```powershell
dotnet build .\EvilIslands.DatabaseEditor.slnx -c Release
dotnet run --project .\src\EvilIslands.DatabaseEditor.App -c Release
```

После запуска выберите исходный `database.res`. Для экспериментов рекомендуется заранее работать с копией, даже несмотря на защиту от перезаписи.

Загрузка главного окна отдельно проверяется при русской региональной культуре командой:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.UiSmoke -c Release
```

Для проверки реального каталога и ленивой загрузки полей можно дополнительно передать путь к базе:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.UiSmoke -c Release -- "D:\staging\database.res"
```

Если WPF всё же завершится с необработанной ошибкой, полный стек будет сохранён в `%LOCALAPPDATA%\EI Database Studio\logs`, а диалог покажет понятную первопричину и путь к журналу.

Основные сочетания клавиш:

- `Ctrl+O` — открыть базу вручную;
- `Ctrl+F` — поиск с задержкой обновления 180 мс;
- `Ctrl+E` — подтвердить переход в режим редактирования;
- `Ctrl+Insert` — добавить в конец текущей таблицы копию выбранной строки;
- `Ctrl+Z` / `Ctrl+Y` — отменить / повторить изменение;
- двойной щелчок или `F2` — открыть выбранную клетку для ввода;
- `Enter` / `Esc` — применить или отменить незавершённый ввод клетки;
- `Ctrl+C` — скопировать выбранные клетки вместе с табличной структурой;
- `F5` — повторная валидация;
- `Ctrl+Shift+S` — «Сохранить копию…».

Диалог сохранения предлагает пользовательский staging-каталог `Документы\EI Database Studio\staging` и имя `<source>.edited.res`. Путь источника и любой уже существующий файл отклоняются на нескольких уровнях приложения.

## Проверочный контур

По умолчанию harness использует два известных файла, если они существуют:

- `C:\GOG Games\Evil Islands\Starter\MODS\JamaisVu135\res\database.res`;
- `C:\GOG Games\database.res`.

Запуск:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.Verification -c Release
```

Произвольный источник можно передать повторяемым параметром `--source`:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.Verification -c Release -- `
  --source "D:\staging\database.res" `
  --source "D:\staging\database-after-db-editor.res"
```

Для каждого существующего источника выполняются:

1. SHA-256 до проверки и открытие только для чтения.
2. Разбор заголовка RES, каталога и границ всех ресурсов.
3. Разбор границ TLV-чанков внутренних баз.
4. Проверка каталога из восьми БД, 26 уникальных таблиц, статусов редактирования и полного покрытия всех записей.
5. Проверка полной схемы всех фактически найденных полей, отсутствия raw Hex, native-типов и виртуальных колонок списков, битов и вложенных структур.
6. Проверка точной схемы всех 51 материалов и наличия записи `powerhit` в `spells.sdb`.
7. No-op `Save As` и полное побайтовое сравнение с источником.
8. Числовое изменение `powerhit.Price` в памяти с записью только в новый временный файл.
9. Отдельное увеличение CP1251-строки `powerhit.Name` на один байт для проверки пересборки длин чанков и смещений RES.
10. Проверка, что в изменённых копиях отличается только `spells.sdb`, а остальные ресурсы идентичны побайтово.
11. Повторное открытие и валидация каждого созданного файла.
12. Отказ при изменении staging-источника после открытия и отсутствие незавершённых `.partial-*` файлов.
13. Негативные проверки значений, точный payload-снимок Undo/Redo, неканонический Boolean и побайтовый Reset.
14. Запрет синтетического `Starter\MODS` и, при наличии системного разрешения, пути через symlink/junction.
15. Динамическое обновление `powerhit.CodeName`, имени записи и полный возврат к исходному состоянию.
16. Детерминированность и отмена семантической проверки, точная локализация сообщений, а также пробы дубликата/пустого ключа, неизвестной ссылки и выхода за диапазон с полным Reset.
17. Клонирование материала и прототипа монстра, Undo/Redo добавленной строки, блокировка дубликата, сохранение уникальной строки и повторное открытие копии.
18. Точная hash-bound проверка сообщений вложенной магии для известных ревизий БД, включая энергию, сложность и ограничение восьми рун.
19. Повторный SHA-256 источника.
20. Вывод времени, выделенной управляемой памяти и рабочего набора процесса.

Отсутствующий стандартный путь помечается как пропущенный. Если не найден ни один источник, harness завершится без записи файлов и сообщит, что проверять нечего.

Созданные harness копии сохраняются в указанном в отчёте уникальном каталоге `%TEMP%\EvilIslands.DatabaseEditor.Verification\run-*`, чтобы их можно было исследовать вручную. Harness не удаляет и не переносит пользовательские файлы.

Точные контентные ожидания выбираются только по SHA-256. Для неизвестной БД полностью
проверяются структура, типы, безопасность Save As и round-trip, но точные количества
материалов и предупреждений помечаются как `SKIP`, а не ошибочно сравниваются с другой
ревизией. Текущие известные линии:

| Ревизия | SHA-256 | Семантические сообщения |
|---|---|---:|
| JamaisVu135 от 2026-08-22 | `E77E3E9E94A110C61AC858AC47A4F9D982CEBCDA843897915E24B7041FF0800A` | 176 |
| DBEditor no-op reference от 2026-08-01 | `10CC977D89676F8A072A5C9A20C6C5B45DA9301D6653D35481F2F61D486E2BE2` | 180 |

Контрольный прогон 2026-08-28 на этих двух ревизиях: `PASS=282, FAIL=0, SKIP=2`.
Оба `SKIP` относятся только к невозможности создать junction/symlink без повышенных
прав Windows; проверки формата, схем, добавления строк, вложенной магии, no-op Save As
и неизменности источников пройдены.

## Чистый Preview-handoff

После успешной Release-сборки чистая распакованная папка создаётся командой:

```powershell
.\tools\Build-PreviewHandoff.ps1
```

Скрипт принимает только путь внутри `handoff`, не перезаписывает существующую папку и
помещает туда пять runtime-файлов, `README_RU.txt` и hash-manifest с точным Git commit.
PDB, базы, тестовые результаты, старые `publish-*` и архивы в handoff не попадают.

## Архитектура

| Проект | Ответственность |
|---|---|
| `EvilIslands.DatabaseEditor.Core` | RES/TLV, модель документа, валидация, изменения и безопасный `Save As`; не зависит от WPF |
| `EvilIslands.DatabaseEditor.App` | WPF-интерфейс, тёмная тема, поиск, таблицы, журнал изменений и команды пользователя |
| `EvilIslands.DatabaseEditor.Verification` | автономные интеграционные проверки на реальных базах без тестовых фреймворков и внешних пакетов |
| `EvilIslands.DatabaseEditor.UiSmoke` | runtime-загрузка App/MainWindow XAML под `ru-RU`, locale-зависимые конвертеры, контраст ключевых стилей и активация навигации |

Такое разделение позволяет тестировать двоичный формат независимо от интерфейса и не связывает сохранение базы с состоянием окна.

## Производительность

Основные принципы реализации:

- один снимок входного файла в памяти вместо повторного чтения с диска;
- представление неизменённых данных срезами `ReadOnlyMemory<byte>`;
- единый индекс восьми структурных DB-ресурсов и 26 таблиц;
- индексация ресурсов по имени без повторного линейного поиска;
- виртуализация строк и отложенное обновление фильтра в WPF;
- пакетная замена UI-коллекций одним уведомлением вместо тысяч перерисовок;
- прямой типизированный адаптер между WPF и Core без reflection;
- описатели столбцов строятся только из метаданных и не декодируют значения;
- списки и битовые маски раскрываются виртуальными read-only колонками без дублирования физических TLV-полей;
- благодаря виртуализации редакторы создаются только для показанных клеток, а не для всех 87 924 полевых чанков;
- значения полей декодируются по требованию и затем кешируются;
- неизменяемая структурная часть семантической проверки вычисляется один раз при открытии;
- повторная проверка после редактирования выполняется с отменой в фоновом потоке и не подвешивает WPF;
- повторное использование исходных байтов для неизменённых ресурсов;
- асинхронное открытие и сохранение, чтобы не блокировать интерфейс.

Числа из verification harness являются диагностикой конкретного компьютера, а не жёстким универсальным нормативом. Регрессией следует считать устойчивое ухудшение относительно сохранённого базового результата на той же машине.

## Формат и ограничения

RES начинается с сигнатуры `0x019CE23C`, содержит каталог 22-байтовых записей и пул имён. Внутренние базы используют TLV-подобное кодирование: идентификатор поля, компактная или расширенная длина и полезная нагрузка. Строки старых игровых баз обычно закодированы в Windows-1251.

Текущие ограничения:

- все восемь табличных ресурсов и 26 секций распознаются и разделяются в интерфейсе;
- все 380 физических полей имеют подтверждённый тип; в проверенных базах не осталось колонок raw `Hex`;
- 578 отображаемых колонок включают фиксированные массивы, пять shop-битов, смешанные структуры защиты, вложенные параметры следов и типизированные списки;
- десять таблиц — `items.materials` и девять секций `units.udb`/`spells.sdb` — имеют текущие типизированные схемы редактирования и разрешают добавление клона выбранной строки в конец;
- остальные 16 таблиц полностью типизированы для просмотра, но намеренно остаются read-only до отдельного round-trip этапа редактирования каждой группы;
- 54 ресурса `*.adb` остаются служебными passthrough-данными в каталоге RES;
- неподтверждённая игровая семантика получает нейтральное имя поля, но бинарный тип и layout не угадываются;
- структурно корректный файл не гарантирует логическую корректность всех игровых ссылок;
- диагностические предупреждения Preview являются неблокирующими подсказками с точной таблицей, записью и полем; данные автоматически не исправляются;
- только отсутствие/дубликат технического ключа новой строки или неверный физический ID нового материала блокирует `Save As`, пока пользователь не исправит значение;
- добавление выполняется лишь в конец: вставка между существующими строками, удаление и перестановка намеренно недоступны, потому что физические индексы используются движком;
- редактор не запускает игру, не управляет модами и не заменяет резервное копирование;
- перед установкой результата в игру нужна отдельная проверка на копии мода.

Исходный `database.res` и каталоги игры не являются тестовыми выходными каталогами проекта.

В DBEditor no-op reference семантический проход показывает 180 неблокирующих
предупреждений: пять прежних сообщений и 175 по вложенной магии. В актуальной
JamaisVu135 четыре отсутствовавшие ссылки `Base Race` уже исправлены, поэтому при
неизменившемся наборе из 175 сообщений вложенной магии итог равен 176. Общая magic-
часть содержит 155 превышений сложности ручной вставки, 10 превышений энергии, 3
случая более восьми распознанных рун, один несовместимый тип материала и по два
повреждённых item/spell-описания с двумя неизвестными составными рунами. Категории
могут пересекаться в одной записи. Значения `none`, `-3`, `Int32.MaxValue`, `xa`/`xa0`
и другие подтверждённые legacy-sentinel учитываются правилами и не создают шум.

Превышение энергии или сложности не означает, что `database.res` не загрузится: уже записанное в descriptor заклинание создаётся низкоуровневым путём. Сообщение означает, что такая комбинация не проходит штатные ограничения ручного конструктора/вставки в лагере. Проверка повторяет порядок вычислений движка: все распознанные руны влияют на стоимость, затем индексы рун сортируются, а `ic`/`it` ищутся только среди первых восьми.

## Безопасный план развития

1. **Фундамент и полный каталог — выполнено.** Разбор RES/TLV, тёмный интерфейс, восемь БД/26 таблиц, поиск, виртуализация, валидация и чтение исходника без записи.
2. **Контролируемое редактирование — расширенный этап выполнен.** Редактируются только поля с известной схемой в `items.materials`, `units.udb` и `spells.sdb`; Undo/Redo и возврат к оригиналу восстанавливают исходные байты, а не только отображаемый текст. Новая строка создаётся независимым клоном выбранной записи и добавляется только в конец разрешённой таблицы.
3. **Полное read-only отображение — выполнено.** Все 26 таблиц и 87 924 поля типизированы; legacy-конфликты проверены по исходникам движка, обе реальные базы проходят no-op round-trip побайтово.
4. **Семантические проверки — расширенный этап выполнен.** Добавлены обязательные и уникальные технические ключи, подтверждённые ссылки между материалами, предметами, перками, расами, зонами попадания, заклинаниями и шаблонами, allowlist-проверки enum/диапазонов/списков/масок и аудит вложенной магии оружия/доспехов. Legacy-sentinel учитываются явно; предупреждения ничего не исправляют, а сохранение блокируют только пустые или повторяющиеся ключи новых строк.
5. **Сравнение и пакетные операции.** Сначала только отчёт различий двух баз; массовое применение изменений — лишь после формата проекта, предварительного просмотра и возможности отмены.
6. **Установка в игру — отдельная будущая функция.** Она не входит в Preview и может появиться только как явно подтверждаемая операция с резервной копией, проверкой целевого мода и журналом действий.
