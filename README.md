# Редактор БД от Атамана

Схема и примеры пространственных целей Kimodo: [Kinematic Constraints Config](docs/testing/database-editor-kimodo-constraints-v1-20260930.md). Для заполненного JSON требуется генератор `spatial-v1`; пустой JSON сохраняет обычную генерацию.

Версия исходников: **215**.

Версия 215: чтение звука, атласов эффектов и каталогов анимаций/моделей без копии
целого PAK; поиск анимаций учитывает профиль, Base, loose и tombstones и обновляет
индекс при изменении источников. Снимки БД для Малахита переиспользуются, а правки
только скрипта сохраняют неизменяемые записи БД. Явный выбор RES не подменяется
соседним PAK; файловый менеджер проверяет известные database/texts PAK до замены.
[Область аудита, проверки и замеры 215](docs/testing/pak-audit215.md).
Для согласованной сборки из задания `tools/Publish-Current.ps1 -ModulePackagePath`
принимает проверенный пакет Малахита, не устанавливая его в основной комплект.

Версия 214: поиск текстур выполняется в фоне и не удерживает таблицы в состоянии
занятости. Каталог для поиска/предпросмотра читает имена и приоритеты; содержимое
текстур проверяется при просмотре и полной проверке F5. Смена БД/источников и закрытие
отменяют применение старого результата. Base PAK подключаются после ресурсов мода;
базовые FIG сохраняют свою классификацию UV независимо от расширения RES/PAK.
Предпросмотр использует общий ограниченный кэш каталогов и до 256 МиБ неизменяемых
MOD/BON с проверкой изменений источника; чтение моделей/текстур не копирует целый PAK.
У гоблинов/огров без составной кожи используются явные текстуры расы. Ошибка текстуры
предмета оставляет видимой геометрию с диагностикой. Результаты и границы аудита:
[проверка 214](docs/testing/preview214.md).

Версия 213: чтение PAK выполняется внутри редактора через общий нативный читатель
движка (`EvilIslands.PakReader.dll`, x64). База и тексты больше не распаковываются
в тысячи временных файлов; каталог текстур читается без копирования целых архивов
и запуска упаковщика для каждого MMP. Контрольные суммы таблицы и payload проверяет
тот же код `rebuild64/Pak`; запись остаётся через EIRebuild64Pack и его транзакции.
Для сборки нужен MSVC v143 x64: `tools/Build-PakReader.ps1` вызывается автоматически.
Он сверяет исходники общего читателя с `native/pak-reader.sources.sha256` и собирает
DLL/PDB в `artifacts/pak-reader`; publish включает их в полный комплект.
Исходники rebuild64 не изменяются. При изменении общего читателя требуется проверка
совместимости и обновление source pin, а не ручная подмена DLL в готовом комплекте.

Версия 210: просмотр персонажей и предметов и проверка связанных ресурсов больше не отклоняют контейнер модели из-за размера свыше 128 МиБ. Поддерживается установленная unhufe.mod размером 147,26 МиБ; проверки структуры RES, диапазонов записей и геометрии сохранены. Лимиты предпросмотра текстур не менялись.

Версия 209: кнопка «Удалить строку» удаляет выбранную последнюю строку поддерживаемой таблицы, в том числе ранее сохранённую. Проверяются ссылки и возможные использования внутри БД; при их наличии удаление блокируется. Удаление из середины запрещено, чтобы не сдвигать физические индексы. Изменение поддерживает Ctrl+Z/Ctrl+Y до сохранения; тексты и ресурсы не удаляются. Использования в картах, Lua и сохранениях нужно проверить отдельно.

Версия 208: столбцы «Название RU», «Описание RU» и «Ключ texts.res» добавляются только в таблицы с предусмотренными текстовыми связями. У прототипов рычагов этих связей нет, поэтому при вставке диапазона редактор больше не требует создать для них тексты. Счётчик столбцов учитывает это же условие.

Версия 200: общий просмотр и редактор применяют оригинальную поправку корня ANM по высотам ADB и росту модели. Сами дорожки и численные поля ANM остаются сырыми; мышь, генерация, опора и JSON-цели переводят игровую позицию обратно перед записью. Открытие старого клипа не меняет его данные. При смене пространства старого проекта сохраняются клип и история, а фиксации стоп/контакты снимаются с сообщением. Ненулевой сдвиг центра расы и размещение на игровом рельефе этим исправлением не воспроизводятся.

Версия 199: Kimodo принимает проверяемый JSON с точками корня, кистей/стоп и позиционной позой текущего кадра. Цели действительно подаются в native sampler как observed/mask; после импорта точки корня и достижимые конечности доводятся в игровом скелете. Черновик, seed, исходный JSON, разрешённые цели и исходные потоки сохраняются для повторного импорта. Остальные суставы остаются приближёнными, совместное требование точных idle-переходов и JSON не поддержано; игровой просмотр и контакт с предметом требуют отдельной проверки.

Версия 198: в форме Kimodo seed по умолчанию равен 0 — перед запуском редактор выбирает случайное положительное число. Фактический seed виден после создания клипа и записан в историю генерации; его можно ввести вручную для повторения. Кнопка «Ещё вариант» использует следующий номер после фактически применённого seed. Введённый ненулевой seed передаётся без изменения.

Версия 197: генератор запоминает последний текст, пожелания «чего избегать» и параметры; кнопка в редакторе повторяет запрос с новым seed. Kimodo принимает только один текстовый запрос: пожелания добавляются в него как инструкция Avoid, а не как отдельное отрицательное условие модели. Новый клип берёт точные первый и последний кадры выбранной анимации покоя и смешивает соседние кадры; совместимость дорожек проверяется до запуска генератора. Промежуточное движение Kimodo создаёт независимо, без conditioning на исходный ANM. Созданные клипы переключаются в одном окне редактора с общей историей ANM. Галочка «Показывать точки и оси» скрывает только накладку управления, не меняя анимацию. Автоматические проверки не подтверждают плавность произвольного движения и работу в игре.

Версия 195: проекты `.eianim` сохраняют снимок исходного ANM и скелета, поэтому созданный или полученный через Kimodo клип можно восстановить вместе с историей и настройками без отдельной записи ANM. Восстановление проекта не даёт права перезаписать сторонне изменённый ANM; старые проекты без снимка открываются только с неизменённым исходником. Операции изменения длины и высоты клипа соблюдают фиксацию стоп и отклоняются атомарно, если опора нарушится. Kimodo сохраняет исходные потоки и параметры до игрового импорта, записывает SHA-256 генератора и весов, причину отказа и позволяет повторить импорт из истории без инференса. Результат генерации по-прежнему требует просмотра и проверки в игре.

Версия 194: генерация движения учитывает видимые стопы в броне и их привязку к скелету. Геометрия проверяется до запуска Kimodo; высота определяется по фактической поверхности стоп с сохранением приседаний и отрыва от земли.

Версия 193: компактный вид распространён на все вкладки нижней панели. У текстур поиск, фильтр и команды собраны в короткую переносимую строку. У модели уменьшены элементы управления, сведения о ресурсах раскрываются отдельно. У визуальных эффектов компактные поиск и таблица, подробные пояснения доступны по раскрытию. Сохранённые размеры, фильтрация и команды не меняются.

Версия 192: нижняя панель текстов и звука компактнее: строки 28 пикселей, заголовки 30, уменьшены отступы и кнопки. Поиск ограничен шириной 320 и высотой 28 пикселей. Длинное описание видно при наведении и доступно для редактирования; сохранённая высота панели и разделители не меняются.

Версия 191: строки БД/Lua компактнее; Lua-столбцы имеют короткие заголовки и меньшую начальную ширину. Наведение на ячейку показывает назначение поля и источник, а не дублирует значение; диагностические сообщения БД сохраняют приоритет. Неописанное влияние поля отмечено явно. Полное значение доступно в строке формул.

Версия 190: единая целочисленная нумерация редактора без старого префикса `0.7.0-preview`. Источник номера — `EditorRevision` в `Directory.Build.props`; интерфейс и ProductVersion показывают этот номер, Windows FileVersion — `190.0.0.0`. AssemblyVersion остаётся стабильным внутренним идентификатором совместимости DLL, а не номером продукта. Исторические записи ниже сохраняют прежние обозначения.

Preview 189: кнопки «Открыть database.res» и «Открыть последнюю БД» используют приглушённый зелёный фон с мягкой подсветкой при наведении и заметной рамкой клавиатурного фокуса.

Preview 188: главная страница показывает последнюю БД и отдельные карточки редактора, Малахита, редактора анимаций и локальной модели. Версия встроенного редактора анимаций совпадает со сборкой хоста; Малахит без номера ревизии определяется по совокупному SHA-256 трёх DLL, а не по старой версии 0.4.0. Метаданные `buildRevision` и `builtAtUtc` в манифесте модуля поддерживаются, если присутствуют. Выбор модели читает установленный Малахит своим read-only resolver; главная проверяет файлы и не запускает сервер или генерацию. Пути и полные идентификаторы доступны в подробностях. Убраны повторяющиеся сообщения о режиме редактирования; сохранение появляется после открытия БД.

Preview 187: поддержана автономная структура игры с portable-defaults.xml и Base/Res. При открытии БД мода используется его config.ini с исходным порядком архивов, затем общие ресурсы Base. Старая структура игры также поддерживается. Папка портативной игры распознаётся защитой записи.

Preview 186: предпросмотр прототипов показывает второй посох, меч, кинжал и щит по деталям модели левой руки. Второй предмет имеет отдельный материал и следует анимации своей кости; первое оружие и явная внешность MOB сохраняются. Предпросмотр показывает комплект прототипа, а не динамический выбор оружия игрой по состоянию и навыкам. Запасные лук/арбалет не добавляются в левую руку.

Preview 185: каталог объектов карт перестроен в три колонки: список моделей слева, увеличенный по высоте 3D-просмотр в центре, компактные настройки справа. Общий размер и выбор MMP остаются на виду; параметры формы FIG/BON раскрываются по необходимости. Список и панель настроек можно расширять разделителями, подробные пояснения доступны в подсказках. Работа поиска, настройки масштаба и текстур не меняют игровых файлов.

Preview 184: каталог объектов карт поддерживает морфинг FIG/BON по трём осям (сила, ловкость, рост) с нейтральным значением 0,50, отдельный общий масштаб 25–300% для любых моделей и подбор MMP для основного и второго слота из доступных ресурсов. Поиск MMP живой; точное совпадение имени модели предлагается автоматически. Камера сохраняется при изменении формы и размера, чтобы масштаб был виден. Выбор влияет только на предпросмотр, не записывает текстуры или морф в карту/RES. Для FIG1 морф по осям не имеет эффекта, но общий масштаб работает. Полный игровой вид конкретного экземпляра зависит от настроек карты и состава доступных архивов.

Preview 183: кнопки каталога объектов карт, подключения texts.res, звука и источников текстур перенесены из верхнего блока в прокручиваемый раздел «Служебное» после «Квесты и скрипты» (Малахит). Действия и привязки сохранены.

Preview 182: кнопка «Объекты карт из RES» открывает независимый от выбранной записи БД каталог всех `.mod` в RES рядом с базой. Есть живой поиск, фильтр архива, источник каждого ресурса и вращаемый 3D-предпросмотр модели по вложенным MOD/BON. Каталог также включает модели существ и предметов, чтобы не пропустить карту по нестандартному имени. Если текстура задаётся конкретной картой, геометрия показывается серой; файл карты для этого просмотра не загружается.

Preview 181: окно сравнения владеет своей сценой; события загрузки, видимости и смены контекста больше не запускают загрузчик БД, очищавший модель. Проверка воспроизводит очистку на Loaded/DataContext до исправления и сохранение модели после него.

Preview 180: в сравнении сгенерированного варианта есть «Тень оригинала»: обычная модель показывает вариант, голубая полупрозрачная — исходное движение на том же кадре. Включение из режима оригинала подготавливает вариант; отключение не сбрасывает кадр или камеру. «Показать оригинал» выключает наложение.

Preview 179: переключение оригинала и варианта больше не пересоздаёт сцену с Т-позой. Предыдущая поза сохраняется до подготовки следующей, текущий кадр и камера не сбрасываются; первая загрузка показывается после применения позы.

Preview 178: «Вариант текущей анимации…» генерирует движение для сравнения с открытым клипом. Можно выбрать кадры и части, силу изменения, принять или отменить. При принятии сохраняются ID и длина, доступен один Undo; запись выполняется обычным сохранением. Kimodo не получает исходный клип как условие: это генерация по тексту и последующее смешивание, а не семантическое редактирование исходника.

Preview 177: одна основная кнопка ADB: «Добавить в ADB» для клипа без записи и «Применить изменения» для существующей записи. Без выбора кнопка недоступна; добавление использует введённые параметры и остаётся в черновике до сохранения.

Preview 176: флаги ADB выбираются на русском: галочки оружия, событий и совместимости с экипировкой, списки вариантов действия и направлений. Исходные hex-коды скрыты в разделе для опытных пользователей; неизвестные биты сохраняются.

Preview 175: в окне ADB под полями «Действие», «Стадия» и «Состояние» отображаются пояснения выбранных значений. Они обновляются также при ручном вводе hex-флагов. Добавлены различие действия и стойки, объяснение цикла и пример регистрации танца.

Preview 174: генератор автоматически рассчитывает положение над землёй по стопам SOMA30 и геометрии стоп игровой модели. Ручной выбор опорной анимации убран; исходная высота старого клипа больше не влияет на результат. Сохраняются отрыв от земли и изменение позы при приседании. Прогноз исходной высоты стоп переносится с масштабом скелета; это не физический решатель контактов рук, тела или скольжения стоп. Уже сохранённые клипы не переписываются.

Preview 173: в игровом списке ADB добавлена отдельная кнопка «Удалить клип ANM…»: удаляет вложенный или старый плоский клип с резервной копией и обновляет просмотр. Используемые в сохранённом ADB клипы защищены от удаления. Запись ADB можно физически удалить только с конца списка; удаление из середины запрещено, чтобы не менять номера других записей. Для середины доступна замена ID клипа. Неактивная заглушка не вводилась: нулевая вероятность не гарантирует отключение всех способов выбора.

Preview 172: в игровом списке ADB можно добавлять записи без шаблона. Начальные значения показаны явно, длина берётся из ANM; копирование настроек старой записи необязательно. Добавлены удаление с предупреждением о сдвиге индексов и отмена изменений черновика. Удаление не удаляет клип ANM. Изменения записываются только кнопкой сохранения с резервной копией.

Preview 171: генератор различает «Повтор на месте» и «Одно действие с перемещением». Для повтора снимается накопленное горизонтальное смещение и сводятся последние кадры с началом; вне короткого перехода сохраняются вертикальные движения, сохраняется опорная высота модели. Разовое действие сохраняет траекторию и открывается без повтора. Проверка стыка зависит от включённого повтора; проверки резких скачков остаются. Исходные потоки Kimodo, промпт, параметры и скелет переноса сохраняются в `%LOCALAPPDATA%/Редактор БД от Атамана/generated-motions`; путь и замечания видны в созданном черновике. Поверхность показывает Z=0 координат ANM, а не низ исходной модели. Это устраняет маскировку неверной высоты, но не имитирует все поправки игрового движка. Качество произвольного движения и контакты стоп требуют просмотра и проверки в игре.

Preview 170: в редакторе анимаций кнопка «Выравнять высоту таза…» позволяет исправить уже записанный клип. Выберите исправную опорную анимацию той же модели; редактор сдвинет только высоту `hp` во всех кадрах, сохранив горизонтальное движение, повороты и изменения высоты между кадрами. Операция отменяется одной командой Undo и не записывает игру до отдельного сохранения ANM. Для старого `twerk1` можно взять высоту `cidle09`; после этого требуется проверка позы и воспроизведения в игре.

## Главное правило безопасности

Приложение ничего не устанавливает в игру автоматически. `Ctrl+S` сохраняет открытый файл с резервной копией, а «Сохранить копию…» по-прежнему создаёт отдельный новый RES. Для открытого файла внутри каталога игры перед прямой записью показывается отдельное подтверждение.

Пока есть несохранённые изменения, раз в 5 минут создаётся отдельный проверенный аварийный снимок в `%LOCALAPPDATA%\Редактор БД от Атамана\recovery`. Он не перезаписывает игровые файлы, содержит согласованную пару `database.res` + `texts.res` и, если звук Брифинга только подготовлен, сохраняет также импортированный MP3/WAV и сведения для его повторной подготовки. Для каждой сессии и каждого исходного `database.res` остаются не больше двух завершённых снимков; manifest записывается последним, поэтому оборванная запись не предлагается для восстановления. После сбоя актуальные копии предлагаются сразу при запуске редактора, ещё до выбора `database.res`; при нескольких сессиях показываются имя базы, исходная папка и время снимка.

При сохранении редактор должен соблюдать следующие инварианты:

- перед прямым сохранением повторно проверяется SHA-256 открытого файла;
- результат полностью строится во временном соседнем файле и повторно разбирается;
- исходное состояние переносится в уникальную `.bak`-копию и проверяется по SHA-256;
- рядом с каждым сохраняемым RES редактор оставляет не больше двух своих последних `.bak`-копий; посторонние файлы с похожими именами не удаляются;
- при сохранении DB/texts исходный файл блокируется от записи и замены, переносится в резервную копию через тот же открытый дескриптор, затем проверенный результат переименовывается на освободившееся место без перезаписи;
- прямая запись в каталог игры требует отдельного подтверждения пользователя;
- «Сохранить копию…» не перезаписывает существующие файлы и не пишет в каталог игры;
- пути через junction/символические ссылки отклоняются;
- неизменённые внутренние ресурсы копируются побайтово;
- созданный RES повторно открывается и проходит структурную проверку;
- открытый файл удерживается от конкурирующей записи на время короткой транзакции;
- отмена пользователем не прерывает фиксацию подготовленного файла; два переименования DB/texts не образуют единой атомарной операции: при аварийном завершении между ними исходные байты остаются в соседнем `.bak`, который потребуется восстановить;
- ошибки записи или валидации не превращают копию в «успешный» результат.

Для проверки этих правил в репозитории есть автономный консольный проект `EvilIslands.DatabaseEditor.Verification`. Он использует только уникальный каталог внутри `%TEMP%` и никогда не пишет рядом с проверяемой базой или в каталог игры.

## Возможности первой версии

- чтение заголовка и каталога контейнера Nival RES;
- отдельный файловый менеджер открывает любой игровой `*.res` ещё до загрузки `database.res`: дерево папок, поиск, размеры и смещения файлов, копирование списка в Excel, извлечение одного или нескольких файлов с сохранением путей, добавление файлов/целых папок через диалог или drag-and-drop, замена и отложенное удаление;
- изменения произвольного RES сначала остаются в памяти и отмечаются как `Добавлен`, `Заменён` или `Будет удалён`; общий Undo/Redo возвращает операции до записи, а сохранение доступно либо в новый архив, либо в текущий RES после подтверждения и проверенной `.bak`-копии;
- универсальная пересборка RES работает потоково: тяжёлые payload не загружаются целиком в память, неизменённые файлы сравниваются побайтово, импорт сверяется по SHA-256, каталог/hash-цепочки строятся заново, результат повторно разбирается; изменившийся после открытия источник отклоняется;
- автоматическое подключение соседнего `texts.res` и ручная команда «Подключить texts.res…», если тексты лежат отдельно;
- автоматическое подключение соседних `JmvSFX.res`, `sfx.res`, `speech.res` и `atamannala.res`, а также ручное подключение одного или нескольких произвольных RES с WAV/MP3/OGG;
- связи звука без загрузки тяжёлых аудиоданных в память: для `acks.db` читаются точные вложенные пути `File`, для `quests.qdb/Брифинги` — каталог `Briefing\<код>`; выбранная строка показывает статус, персонажа, русский текст `#phrase`, путь файла, архив, формат и размер;
- для выбранной реплики Брифинга можно подготовить добавление нового MP3/WAV или точную замену существующего файла; редактор показывает будущие архив и путь ресурса, поддерживает Undo/Redo до записи и в первой версии сохраняет только новый, не существовавший ранее RES вне каталога игры;
- звуковой Save As выполняется потоково даже для большого `speech.res`: неизменённые ресурсы переносятся без загрузки всего архива в память, каталог и hash-цепочки RES пересобираются, результат повторно разбирается, а импортированный звук сверяется по SHA-256;
- MP3 `1.mp3`, `2.mp3`, `2a.mp3` и подобные сопоставляются с номером `#phrase` внутри связанного `BRIEFING <код>` из `texts.res`, поэтому видно, какой персонаж произносит конкретную русскую реплику;
- специальный экран Брифингов показывает полный сценарий в исходном порядке: `#DESC`, `#show`, `#hide`, `#ANIMATION`, `#NOLIPS`, `#CAMERA`, `#phrase` и неизвестные служебные команды; камера, анимация, участники сцены и режиссёрские пометки редактируются в понятной правой панели, а `#NOLIPS` подписан как мысль без движения губ; новые события и реплики вставляются после выбранного шага, выбранный блок можно переместить выше/ниже, продублировать или удалить с полным возвратом через `Ctrl+Z`;
- встроенная неблокирующая проверка Брифинга отмечает повторяющиеся и пропущенные номера `#phrase`, неверные параметры камеры/анимации, `#NOLIPS` без следующей реплики, подозрительный порядок `#show`/`#hide`, реплики без аудио и аудиофайлы без текстовой реплики; фильтр «Только проблемы» ведёт прямо к соответствующему шагу и показывает понятное объяснение;
- три колонки `Ключ texts.res`, `Название RU` и `Описание RU` встроены прямо в соответствующую строку `database.res`; существующий русский текст редактируется там же, а для отсутствующего ресурса показывается точный ожидаемый ключ с пометкой «нет ресурса»;
- если запись ожидает несколько ресурсов, но часть или все отсутствуют, выбор клетки раскрывает снизу каждый конкретный ключ со статусом `Нет ресурса`; надпись `0 из N вариантов` удалена, а рядом с перечнем находится явная кнопка `Создать отсутствующие тексты`;
- вставка и обычное редактирование одной клетки `texts.res` больше не сбрасывают целиком текущую таблицу и каталог из тысяч русских ресурсов; при активном поиске необходимое обновление выполняется после фиксации клетки и объединяет последовательные правки;
- семантический цветовой код отделяет структуру `database.res`, локализацию `texts.res`, технические raw-поля, несохранённые изменения, предупреждения и ошибки; компактная легенда `DB`/`RU` остаётся видимой над таблицей;
- отдельный пункт «Русские тексты» показывает все ресурсы подключённого `texts.res` в одной Excel-подобной таблице с поиском по ключу, названию и описанию; данные доступны даже когда для выбранной строки `database.res` нет точного соответствия;
- в полном разделе «Русские тексты» выбранная клетка открывается в отдельной трёхстрочной строке формул; длинное описание можно нормально читать, вставлять и редактировать, а `Enter`/`Esc` и общий Undo работают так же, как в основной таблице; кнопка `▤` переносит редактируемое строковое значение в крупный встроенный редактор;
- связи строятся по тем же ключам, что и игровой runtime: `UNIT <prototype>`, `MATERIAL`/`MATSHORT`, `WEAPON`/`ARMOR <форма> <совместимый материал>`, `QITEM`, `QUESTITEM`, `SPELL`, `MODIFIER`, `PERK`, `QUEST` и `BRIEFING`;
- нижняя Excel-подобная таблица связанных текстов выбранной строки; для оружия и брони она показывает отдельные записи всех сочетаний формы с материалом;

## Запуск

Для сборки требуются Windows и .NET 9 SDK. Готовый handoff содержит автономный
single-file EXE; установленный .NET и соседние DLL для запуска не нужны. Внешние
NuGet-пакеты проекту не нужны.

```powershell
dotnet build .\EvilIslands.DatabaseEditor.slnx -c Release
dotnet run --project .\src\EvilIslands.DatabaseEditor.App -c Release
```

После запуска выберите `database.res`. Соседние `texts.res` и известные звуковые RES
подключатся автоматически. Отдельные кнопки показывают количество текстов и аудиофайлов;
звуковые архивы из другой папки можно выбрать вместе через диалог подключения. В карточке
реплики Брифинга команда `＋ MP3/WAV…` подготавливает добавление или замену аудио.
`Сохранить в текущий RES` безопасно обновляет подключённый `speech.res` или другой звуковой
архив после отдельного подтверждения, полной проверки и создания `.bak`; для игрового пути
подтверждение отдельно предупреждает о записи в установленный мод. `Сохранить копию…`
оставляет исходник без изменений и создаёт новый проверенный архив.

Кнопка `Открыть архив RES/PAK…` доступна сразу после запуска и не требует открывать
базу. В менеджере архивов выберите папку, добавьте файлы или папку,
замените либо отметьте файлы для удаления и затем используйте `Сохранить копию архива…`.
RES можно сохранить в RES или PAK; копия PAK сохраняет формат PAK и метки удаления.
Явно выбранный RES открывается независимо от наличия одноимённого PAK рядом.
`Перезаписать текущий архив…` создаёт проверенную `.bak`-копию; если тот же архив уже подключён
к основному редактору, прямая запись намеренно блокируется, чтобы две модели не перезаписали
друг друга — в таком случае сначала сохраните копию либо откройте менеджер до базы.

В версии 212 кнопка последней базы находит соседний PAK, если прежний RES удалён при
миграции. Хеш EIRebuild64Pack встраивается при сборке из проверенного SHA256SUMS
принятого rebuild64 и проверяется перед запуском упаковщика. Публикация сохраняет
именно EXE сборки; редактор и упаковщик следует переносить полным комплектом.

Если WPF всё же завершится с необработанной ошибкой, полный стек будет сохранён в `%LOCALAPPDATA%\Редактор БД от Атамана\logs`, а диалог покажет понятную первопричину и путь к журналу.

Основные сочетания клавиш:

- `Ctrl+O` — открыть базу вручную;
- `Ctrl+F` — поиск с задержкой обновления 180 мс;
- `Ctrl+S` — сохранить текущий файл с автоматической `.bak`-копией;
- `Ctrl+Insert` — добавить в конец текущей таблицы копию выбранной строки;
- `Ctrl+Z` / `Ctrl+Y` — отменить / повторить изменение или всю последнюю табличную вставку;
- двойной щелчок — изменить значение непосредственно в клетке; `F2` — перейти в строку формул и выделить полное значение;
- `Enter` / `Esc` — применить или отменить незавершённый ввод клетки;
- в строке формул `Enter` применяет значение, `Esc` возвращает текущее, `Alt+Enter` добавляет перенос строки;
- `Shift`/`Ctrl` + щелчок — выделить диапазон или отдельные клетки;
- `Ctrl+C` — скопировать выбранные клетки в редактор или Excel;
- `Ctrl+V` — вставить клетку/прямоугольник из редактора или Excel;
- `F5` — повторная валидация;
- `Ctrl+Shift+S` — «Сохранить копию…».

Диалог «Сохранить копию…» предлагает пользовательский staging-каталог `Документы\Редактор БД от Атамана\staging` и имя `<source>.edited.res`. Для этой команды путь источника и любой уже существующий файл отклоняются на нескольких уровнях приложения.

## Проверочный контур

По умолчанию harness использует два известных файла, если они существуют:

- `C:\GOG Games\Evil Islands\Starter\MODS\JamaisVu135\res\database.res`;
- `C:\GOG Games\database.res`.

Запуск:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.Verification -c Release
```

Произвольный источник можно передать повторяемым параметром `--source`:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.Verification -c Release -- `
  --source "D:\staging\database.res" `
  --source "D:\staging\database-after-db-editor.res"
```

Для восстановления старого дефекта Preview, который мог разделить руны вложенной
магии на отдельные элементы StringList, предусмотрен доказательный режим. Он читает
повреждённый файл и чистую опорную базу, склеивает только синтаксически замкнутые
группы, чьё полное значение найдено в опорной базе, и создаёт результат исключительно
в уникальном `%TEMP%` без изменения источников:

```powershell
dotnet run --project .\tests\EvilIslands.DatabaseEditor.Verification -c Release -- `
  --repair-source "D:\staging\database.res" `
  --repair-reference "D:\backup\database.res"
```

Для каждого существующего источника выполняются:

1. SHA-256 до проверки и открытие только для чтения.
2. Разбор заголовка RES, каталога и границ всех ресурсов.
3. Разбор границ TLV-чанков внутренних баз.
4. Проверка каталога из восьми БД, 26 уникальных таблиц, статусов редактирования и полного покрытия всех записей.
5. Проверка полной схемы всех фактически найденных полей, отсутствия raw Hex, native-типов и виртуальных колонок списков, битов и вложенных структур.
6. Проверка точной схемы всех 51 материалов и наличия записи `powerhit` в `spells.sdb`.
7. No-op `Save As` для `database.res` и соседнего `texts.res` с полным побайтовым сравнением с источниками.
8. Числовое изменение `powerhit.Price` в памяти с записью только в новый временный файл.
9. Отдельное увеличение CP1251-строки `powerhit.Name` на один байт для проверки пересборки длин чанков и смещений RES.
10. Проверка, что в изменённых копиях отличается только `spells.sdb`, а остальные ресурсы идентичны побайтово.
11. Повторное открытие и валидация каждого созданного файла.
12. Отказ при изменении staging-источника после открытия и отсутствие незавершённых `.partial-*` файлов.
13. Прямое сохранение только временной staging-копии: точность `.bak`, лимит в два последних бэкапа, сохранность постороннего файла с похожим именем, повторное открытие результата и отказ при внешнем изменении файла.
14. Негативные проверки значений, точный payload-снимок Undo/Redo, неканонический Boolean и побайтовый Reset.
15. Запрет синтетического `Starter\MODS` и, при наличии системного разрешения, пути через symlink/junction.
16. Динамическое обновление `powerhit.CodeName`, имени записи и полный возврат к исходному состоянию.
17. Детерминированность и отмена семантической проверки, точная локализация сообщений, а также пробы дубликата/пустого ключа, неизвестной ссылки и выхода за диапазон с полным Reset.
18. Клонирование строк во всех 26 таблицах, Undo/Redo, блокировка пустого/повторного ключа новой строки и повторное открытие сохранённых материалов, оружия, брони и монстров.
19. Точная hash-bound проверка сообщений вложенной магии для известных ревизий БД, включая энергию, сложность и ограничение восьми рун.
20. No-op применение StringList с вложенной магией, эмуляция старого разделения по `;` и точное восстановление исходных TLV-границ.
21. Повторный SHA-256 источника.
22. Вывод времени, выделенной управляемой памяти и рабочего набора процесса.
23. CP1251-редактирование существующего текста, отказ для неподдерживаемого символа и добавление нового ресурса через пересобранную hash-таблицу `texts.res`.
24. Потоковое чтение только каталогов звуковых RES, точное сопоставление `acks.db/File` с WAV и Брифингов с MP3, разбор `#phrase` из `texts.res`, безопасный Save As и прямая запись только временной копии звукового RES с точным `.bak`, повторным разбором, побайтовой проверкой незатронутых ресурсов и отказом при внешнем изменении источника.
25. Монтаж и проверка Брифинга: вставка/перемещение/удаление/дублирование целых событий, новый номер копии реплики, диагностика сценария, фильтр проблем и точный Undo без записи в исходные RES.

Отсутствующий стандартный путь помечается как пропущенный. Если не найден ни один источник, harness завершится без записи файлов и сообщит, что проверять нечего.

Созданные harness копии сохраняются в указанном в отчёте уникальном каталоге `%TEMP%\EvilIslands.DatabaseEditor.Verification\run-*`, чтобы их можно было исследовать вручную. Harness не удаляет и не переносит пользовательские файлы.

Точные контентные ожидания выбираются только по SHA-256. Для неизвестной БД полностью
проверяются структура, типы, безопасность Save As и round-trip, но точные количества
материалов и предупреждений помечаются как `SKIP`, а не ошибочно сравниваются с другой
ревизией. Текущие известные линии:

| Ревизия | SHA-256 | Семантические сообщения |
|---|---|---:|
| JamaisVu135 от 2026-08-22 | `E77E3E9E94A110C61AC858AC47A4F9D982CEBCDA843897915E24B7041FF0800A` | 176 |
| DBEditor no-op reference от 2026-08-01 | `10CC977D89676F8A072A5C9A20C6C5B45DA9301D6653D35481F2F61D486E2BE2` | 180 |

Контрольный прогон 2026-08-28 на этих двух ревизиях: `PASS=348, FAIL=0, SKIP=2`.
Оба `SKIP` относятся только к невозможности создать junction/symlink без повышенных
прав Windows; проверки формата, схем, добавления строк, вложенной магии, no-op Save As
и неизменности источников пройдены.

Целевой прогон Preview 16 от 2026-08-29 на active JamaisVu135:
`PASS=191, FAIL=0, SKIP=4`, UI smoke — `PASS`. Каталог четырёх звуковых RES содержит
`8 464` WAV/MP3/OGG и строится примерно за `29 ms` с выделением `10,3 MiB`, без чтения
аудиоданных целиком. Пропуски относятся к отсутствующей
контентной baseline для пользовательской базы и недоступному без повышенных прав
созданию junction/symlink. Дополнительно настоящий WPF `DataGrid` проверяет завершение
редактирования новой строки без бесконечного цикла Dispatcher, автосоздание связанных
`texts.res`, звуковую панель Брифинга с персонажем и текстом реплики и атомарный Undo.
UiSmoke также отклоняет второй аргумент без расширения
`.png`, поэтому путь `database.res` или `texts.res` больше нельзя перезаписать снимком.

возвращает оба RES. Реальное изменение вычисляемого значения по-прежнему отклоняет весь пакет.
Каждые 5 минут несохранённая рабочая модель записывается как проверяемая аварийная пара
в `%LOCALAPPDATA%`; хранятся два последних полных снимка, а оборванные снимки игнорируются.
После аварийного завершения редактор предлагает открыть копию отдельно; подготовленный
MP3/WAV сохраняется вместе с manifest и автоматически возвращается при доступном исходном
звуковом архиве.

Preview 30 превращает основные области редактора в сохраняемый модульный макет. Мышью
можно менять ширину левой навигации, высоту обычной и полной строки формул, высоту нижней
области, соотношение связанных текстов и звука, а также ширину списка сцен и сценария
Брифинга. Отдельно запоминаются размер главного окна и встроенного редактора длинного текста;
кнопка `Макет` возвращает проверенные размеры по умолчанию. Все разделители двигают содержимое
в реальном времени и имеют безопасные пределы, чтобы панель нельзя было потерять за краем.
Отложенные исправления тоже включены: аварийная копия предлагается сразу при запуске, а
Excel-вставка сравнивает вычисляемые числа по значению (`1,14` и `1.14` считаются равными).
Реальная попытка изменить вычисляемую колонку всё ещё отменяет весь диапазон, но сообщение
теперь содержит адрес клетки и короткое понятное имя поля без внутренних структур программы.

Preview 31 защищает пользовательскую раскладку от случайного сброса при возврате в окно.
Кнопка в заголовке явно называется `Сбросить макет` и сначала открывает подтверждение с
описанием последствий. Отмена сохраняет текущие размеры панелей и записанные настройки;
стандартная раскладка применяется только после отдельного подтверждения.

Preview 32 исправляет обмен диапазонами с Microsoft Excel и доводит модульный макет до
настоящего вспомогательного окна. `Ctrl+C` публикует выбранный прямоугольник одновременно
как Unicode-текст, CSV и HTML-таблицу; `Ctrl+C`/`Ctrl+V` перехватываются таблицей даже когда
внутри активной клетки открыт текстовый редактор. Блок связанных русских текстов и звука
можно открепить отдельной кнопкой, перенести на другой монитор, изменить его размер и затем
вернуть под таблицу; размер и откреплённое состояние запоминаются между запусками. Интервал
аварийного автосохранения увеличен до привычных пяти минут.

Preview 33 распространяет Excel-совместимый буфер на все таблицы редактора, включая
«Связанные тексты», «Связанные звуковые файлы», каталог `texts.res`, ресурсы, сценарий
Брифинга, журнал изменений и проверку. Редактируемые названия и описания принимают целые
диапазоны из Excel одной пакетной операцией и отменяются одним `Ctrl+Z`; пересчёт связей и
обновление представлений выполняются один раз на весь диапазон, поэтому большая вставка не
подвешивает интерфейс после каждой клетки. Вычисляемые таблицы, например найденные звуки,
копируются в Excel, но остаются защищёнными от прямой вставки.

Preview 34 исправляет направление вставки в уже выделенный прямоугольник. WPF мог оставить
активной не верхнюю левую, а последнюю клетку выделения; редактор ошибочно использовал её как
начало диапазона, сдвигал строки и затем блокировал якобы изменённый служебный ключ
`texts.res`. Теперь диапазон одинакового размера, как в Excel, всегда сопоставляется с
верхним левым углом выделения независимо от активной клетки. Одиночная выбранная клетка
по-прежнему служит обычной точкой начала вставки.

Preview 35 добавляет прямое безопасное сохранение подготовленного MP3/WAV в подключённый
`speech.res` или другой звуковой RES. Перед заменой архив полностью пересобирается во
временный соседний файл, повторно разбирается, сверяет импортированный звук по SHA-256 и
побайтово проверяет все незатронутые ресурсы. Исходник повторно проверяется перед записью,
рядом заранее создаётся проверенная `.bak`-копия, а атомарная замена выполняется только
после отдельного подтверждения; для `Starter\MODS` используется явное предупреждение о
записи в игру. Старый режим сохранения отдельной копии сохранён.

Preview 36 добавляет на экран «Обзор» единое управление резервными копиями всех подключённых
RES. Отдельные строки и кнопки «Восстановить» доступны для `database.res`, `texts.res` и
каждого звукового архива; рядом видны дата, размер и количество штатных `.bak`. Перед откатом
редактор повторно проверяет, что текущий файл не изменился извне, полностью разбирает выбранную
копию соответствующим парсером и требует отдельного подтверждения для пути игры. Текущее
состояние сохраняется в новую проверенную `.bak`, поэтому выполненный откат можно обратить;
после атомарной замены вся рабочая область перечитывается. При несохранённых правках или
подготовленном аудио восстановление отключено, чтобы не потерять изменения в памяти.

Preview 37 добавляет структурный редактор `StringList` и закрывает оставшийся опасный путь
повреждения вложенной магии. Кнопка `☷` в строке формул показывает каждый физический
TLV-элемент отдельно: элементы можно добавлять, дублировать, удалять и перемещать, а поиск
технических имён помогает вставлять ссылки на записи базы. Для предмета с вложенной магией
отдельно показываются форма/материал, код заклинания и модификаторы; после правки редактор
собирает один элемент обратно и применяет весь список одной операцией Undo. Сырой режим
сохранён для совместимости с Excel и ручным вводом, но несбалансированные `[]`/`{}` теперь
отклоняются с точной позицией скобки вместо прежнего аварийного деления текста по `;`.

Preview 39 приводит структурный редактор к общей тёмной теме и убирает стандартные светлые
вкладки WPF. Список, панель выбранного элемента и поиск ссылок получили устойчивую
трёхчастную компоновку с изменяемой границей, сокращённым столбцом типа и подсказками для
длинных значений. Разбор теперь зависит от фактической структуры элемента: поля предмета,
заклинания и модификаторов появляются только для вложенной магии; `steps\\Модель\\Поверхность`
показывается как блок звука шага, остальные пути и простые значения не получают ложных полей
заклинания. Даже фигурные параметры неизвестного немагического блока не считаются
заклинанием без соответствующего контекста поля. Режимы «Структура» и «Сырой текст»
переключаются собственными тёмными кнопками.

Preview 40 устраняет обрезание нижней части карточки «Выбранный элемент»: вся правая панель
структурного редактора получила собственную вертикальную прокрутку, поэтому поиск ссылок и
результаты всегда достижимы даже при минимальном размере окна. Поля `Оружие 1` и `Оружие 2`
в прототипах монстров физически являются одиночными строками, а не `StringList`, но хранят
составное значение оружия с вложенной магией. Для них кнопка `☷` теперь открывает отдельный
структурный режим одного значения: без команд добавления, удаления и перестановки элементов,
с раздельными полями оружия, кода заклинания и модификаторов и с одной операцией Undo.

Preview 41 заменяет ручную сборку строки `предмет[заклинание{модификаторы}]` типизированным
конструктором во всех подтверждённых полях вложенной магии. Форма оружия или доспеха,
совместимый материал, заклинание и каждая руна выбираются отдельно из текущей `database.res`;
если подключён `texts.res`, рядом показываются русские названия. Конструктор рассчитывает
сложность и энергию тем же кодом, что семантическая проверка, и не применяет новую или
изменённую комбинацию с неизвестной ссылкой, несовместимым материалом, отсутствующей руной
`ic`/`it`, превышением восьми рун либо доступной сложности/энергии. Уже существующие legacy-
строки остаются открываемыми без принудительного исправления.

Preview 42 добавляет первый безопасный этап переноса настроек между версиями мода — отчёт
сравнения двух `database.res`. Кнопка на экране «Обзор» открывает вторую базу строго для
чтения и сравнивает все 26 распознанных таблиц: записи сопоставляются по техническому ключу,
а поля — по физическому ID и точному payload. Отдельно видны записи только в текущей или
только во второй базе, добавленные/удалённые поля и изменённые значения. Отчёт поддерживает
поиск, фильтры, копирование клеток в Excel и переход к исходной ячейке текущей базы. Никаких
кнопок массового применения пока нет: просмотр отличий не изменяет ни один RES.

Preview 43 разрешает редактировать отдельные элементы числовых списков прямо в понятных
колонках. В `Прототипах NPC` это `Наука`, `Кража`, `Приручение` и восемь автонавыков от
`Ближнего боя` до `Внимательности`; тот же механизм работает для остальных проекций `ByteList`,
`UInt32List` и `Float32List`. Изменяется только выбранный элемент с сохранением исходного
TLV-представления и соседних значений. Строка формул, обычная ячейка и прямоугольная вставка
из Excel используют общий валидатор; один Undo отменяет весь пакет.

Preview 44 добавляет универсальный файловый менеджер Nival RES. Он показывает архив как
дерево папок и таблицу файлов, поддерживает добавление, замену, извлечение и удаление,
работает с большими архивами потоково и применяет тот же fail-closed цикл временной сборки,
повторного разбора, SHA-256 и резервной копии, что остальные безопасные операции редактора.

Preview 45 перестраивает RES-менеджер в трёхпанельный файловый интерфейс: дерево папок,
компактный список и скрываемые свойства выбранного ресурса. Адресная строка и кнопка перехода
вверх упрощают навигацию, глобальный поиск временно добавляет колонку папки, а нижний журнал
показывает каждое подготовленное добавление, замену или удаление с отдельной отменой. Размеры
окна, дерева и панели свойств запоминаются. Имена ресурсов читаются и записываются строго в
Windows-1251: кириллические папки больше не превращаются в `???`, а неподдерживаемые символы
отклоняются до пересборки архива.

Preview 46 исправляет нечитаемый светлый выпадающий список в структурном редакторе и
завершает типизированное редактирование таблиц. Отдельно меняются элементы вложенных TLV-
структур, девять упакованных параметров каждого слоя брони и подтверждённые перечисления:
типы быстрых предметов и лута, школы и подтипы магии, виды урона, движения, зон попадания,
оружия и модификаторов. Один изменённый или отсутствующий дочерний элемент больше не делает
всю колонку недоступной. Для необратимой краткой расшифровки редактор оставляет рядом
редактируемое физическое поле. Названия оставшихся `Unk`-полей заменены по штатным native-
структурам игры; автоматический тест отклоняет выпуск при появлении нового безымянного поля.

Preview 47 убирает последний технический hex из обычного вида `acks.db`. Поля «Выбор»,
«Движение», «Атака», «Заклинание», «Подбор» и остальные события теперь показывают читаемую
сводку вариантов, а кнопка `☷` открывает таблицу «Файл», «Вероятность», «Описание», «Ключ»
и «Флаги условий». Маска условий для события «Скука» дополнительно переводится в названия
состояния, аллода, времени, места и погоды. Изменяется только выбранное дочернее TLV-поле;
неизвестные чанки и заголовки сохраняются, а исходный hex остаётся доступен в «Технических
полях» для диагностики.

Preview 48 проводит единый аудит оформления всех XAML-окон. Кнопки, текстовые поля,
выпадающие и обычные списки, флажки, таблицы, полосы прокрутки, разделители и раскрывающиеся
панели теперь используют общие размеры, отступы, состояния наведения, фокуса, выбора и
блокировки. Выпадающие списки получили собственный тёмный шаблон вместе с popup-частью и
элементами списка, поэтому системная светлая тема Windows больше не появляется в
структурном редакторе или сравнении баз. Локальные стили строк и списков наследуют общую
тему, а UiSmoke отдельно блокирует выпуск без собственных шаблонов и единых размеров таблиц.

Preview 54 добавляет редактирование отображаемого названия прямо в специальный экран
«Брифинги». Поле в шапке сценария изменяет только заголовок связанного ресурса
`BRIEFING …` в `texts.res`: технический ключ (`s1_3` и подобные) и последовательность
событий остаются прежними. Изменение проходит через общий валидатор Windows-1251,
появляется в журнале и полностью поддерживает Undo/Redo.

Preview 55 заменяет неоднозначную кнопку технических полей явным выбором из трёх режимов:
понятные расшифровки, полный объединённый набор и только физические исходные поля
`database.res`. Доступность теперь определяется реальным отличием наборов колонок, а не
условным размером таблицы, поэтому в «Боевых криках» с 6 видимыми из 11 полей переключатель
работает. Счётчик подписывает видимое и полное количество словами и отдельно оставляет
добавленные колонки RU/звука.

Preview 56 завершает редактор вариантов реплики `acks.db`. Над таблицей появились команды
`＋ Вариант`, `Дублировать`, `↑`, `↓` и `Удалить`; они работают и когда исходный список
полностью пуст. Изменения остаются внутри окна до `Применить варианты` и попадают в общий
Undo одной операцией. Кодировщик составного списка теперь безопасно меняет число и порядок
TLV-элементов, копирует неизвестные служебные данные при дублировании и отказывается менять
структуру, если обнаружены неподдерживаемые внешние служебные блоки.

Preview 57 вводит единое выравнивание таблиц во всём редакторе. Текстовые, числовые,
расшифрованные и технические значения, связанные тексты и звук, списки структурных
редакторов, отчёты проверки, сравнение баз и файловый менеджер RES теперь располагают
содержимое ячеек по центру по горизонтали и вертикали. Заголовки колонок используют то же
выравнивание, а после F2 или двойного щелчка текст в поле ввода не смещается к краю.

Preview 58 превращает структурный редактор строковых списков в предметный конструктор.
Для подтверждённых полей можно явно выбрать заклинание или боевой навык, оружие либо броню.
Формы оружия и доспехов показываются раздельно, после выбора формы список ограничивается
совместимыми материалами. В предмет можно по желанию вложить заклинание и набрать его руны
отдельными строками; тот же выбор заклинания и рун работает без предмета в полях заклинаний.
Неизвестные legacy-значения остаются доступны через режим точного значения и не заменяются
автоматически. Перед применением общий валидатор проверяет ссылки, совместимость материала,
обязательную руну `it`/`ic`, число рун, сложность и энергию.

## Постоянная папка готового редактора

Обычная локальная сборка всегда обновляет `builds/dbeditor/current` корня проекта вместе с Малахитом:

```powershell
.\tools\Publish-Current.ps1
```

Запуск: `builds/dbeditor/current/EvilIslands.DatabaseEditor.exe`. Перед обновлением закройте
редактор из этой папки. Номер версии меняется в программе, путь остаётся прежним.
Для переноса уже проверенной сборки без пересборки используйте
`-PackagePath <папка с host-manifest.sha256.json>`: модуль уже входит в этот комплект.
При сборке единственный источник модуля — `builds/malachite/current` корня проекта.
Корень находится подъёмом от скрипта до `RULES.md`. Слот заполняет приёмка задания
Малахита (первоначально NEWPROJ09). При отсутствии папки сборка отказывает с сообщением;
параметра `-ModulePath` и копирования прежнего Modules больше нет.
Модуль копируется в `Modules/malachite/current` без PDB, включая вложенные папки;
PDB Малахита остаются в его слоте. Эта локальная сборка требует .NET 9 Desktop Runtime.
Посторонние файлы не удаляются; изменённые вне сборки файлы не затираются молча.
`Build-PreviewHandoff.ps1` без параметров также обновляет current.
Датированные пакеты больше не создаются для обычного обновления.

Для отдельного обновления из того же слота запустите `tools/Update-Malachite.ps1` без параметров.
Постоянная папка модуля — `builds/dbeditor/current/Modules/malachite/current`.
Имя папки не обозначает версию сборки; прежняя папка `0.4.0` заменена на `current`.
Эта команда копирует проверенный комплект из `builds/malachite/current` без PDB;
при отсутствии слота обновление отказывает. Модуль собирается и принимается отдельно.
DLL и EXE хоста не пересобираются и не заменяются. Проверяются SDK, контракт,
возможности хоста, хэши файлов и закрытый редактор; общий манифест обновляется.
Обновления хоста и модуля используют общую блокировку. Задача «МАЛАХИТ» может
выполнять этот процесс самостоятельно; изменения SDK согласуются с владельцем хоста.

## Исторический автономный Preview-handoff (только явный экспорт)

Preview 59 исправляет четыре ошибки сохранения. `Ctrl+S` сохраняет подготовленный импорт

## Производительность

Основные принципы реализации:

- один снимок входного файла в памяти вместо повторного чтения с диска;
- представление неизменённых данных срезами `ReadOnlyMemory<byte>`;
- единый индекс восьми структурных DB-ресурсов и 26 таблиц;
- индексация ресурсов по имени без повторного линейного поиска;
- виртуализация строк и отложенное обновление фильтра в WPF;
- пакетная замена UI-коллекций одним уведомлением вместо тысяч перерисовок;
- прямой типизированный адаптер между WPF и Core без reflection;
- описатели столбцов строятся только из метаданных и не декодируют значения;
- числовые списки, битовые маски, перечисления, вложенные TLV-поля и упакованные параметры раскрываются редактируемыми виртуальными колонками без изменения соседних значений; необратимые вычисляемые сводки остаются read-only рядом с редактируемым исходником;
- благодаря виртуализации редакторы создаются только для показанных клеток, а не для всех 87 924 полевых чанков;
- значения полей декодируются по требованию и затем кешируются;
- неизменяемая структурная часть семантической проверки вычисляется один раз при открытии;
- повторная проверка после редактирования выполняется с отменой в фоновом потоке и не подвешивает WPF;
- повторное использование исходных байтов для неизменённых ресурсов;
- потоковое копирование payload универсального RES-менеджера без удержания большого звукового архива в памяти;
- асинхронное открытие и сохранение, чтобы не блокировать интерфейс.

Числа из verification harness являются диагностикой конкретного компьютера, а не жёстким универсальным нормативом. Регрессией следует считать устойчивое ухудшение относительно сохранённого базового результата на той же машине.

## Формат и ограничения

RES начинается с сигнатуры `0x019CE23C`, содержит каталог 22-байтовых записей и пул имён. Внутренние базы используют TLV-подобное кодирование: идентификатор поля, компактная или расширенная длина и полезная нагрузка. Строки старых игровых баз обычно закодированы в Windows-1251.

Текущие ограничения:

- все восемь табличных ресурсов и 26 секций распознаются и разделяются в интерфейсе;
- все 380 физических полей имеют подтверждённый тип; в проверенных базах не осталось колонок raw `Hex`;
- 702 отображаемые колонки включают фиксированные массивы, пять shop-битов, подтверждённые перечисления, смешанные структуры защиты, вложенные параметры следов и типизированные списки;
- все 26 таблиц имеют типизированные схемы редактирования и разрешают добавление клона выбранной строки в конец;
- элементы числовых списков, пять shop-битов, подтверждённые enum-значения, вложенные TLV-параметры, упакованные структуры брони и варианты реплик `acks.db` редактируются через понятные поля; техническое исходное представление открывается отдельной командой и не загромождает обычную таблицу;
- 54 ресурса `*.adb` остаются служебными passthrough-данными в каталоге RES;
- неподтверждённая игровая семантика получает нейтральное имя поля, но бинарный тип и layout не угадываются;
- структурно корректный файл не гарантирует логическую корректность всех игровых ссылок;
- диагностические предупреждения Preview являются неблокирующими подсказками с точной таблицей, записью и полем; данные автоматически не исправляются;
- только отсутствие/дубликат технического ключа новой строки или неверный физический ID нового материала блокирует сохранение, пока пользователь не исправит значение;
- добавление выполняется лишь в конец: вставка между существующими строками, удаление и перестановка намеренно недоступны, потому что физические индексы используются движком;
- редактор не запускает игру, не управляет модами и не заменяет резервное копирование;
- перед установкой результата в игру нужна отдельная проверка на копии мода.

Исходный `database.res` и каталоги игры не являются тестовыми выходными каталогами проекта.

В DBEditor no-op reference семантический проход показывает 180 неблокирующих
предупреждений: пять прежних сообщений и 175 по вложенной магии. В актуальной
JamaisVu135 четыре отсутствовавшие ссылки `Base Race` уже исправлены, поэтому при
неизменившемся наборе из 175 сообщений вложенной магии итог равен 176. Общая magic-
часть содержит 155 превышений сложности ручной вставки, 10 превышений энергии, 3
случая более восьми распознанных рун, один несовместимый тип материала и по два
повреждённых item/spell-описания с двумя неизвестными составными рунами. Категории
могут пересекаться в одной записи. Значения `none`, `-3`, `Int32.MaxValue`, `xa`/`xa0`
и другие подтверждённые legacy-sentinel учитываются правилами и не создают шум.

Превышение энергии или сложности не означает, что `database.res` не загрузится: уже записанное в descriptor заклинание создаётся низкоуровневым путём. Сообщение означает, что такая комбинация не проходит штатные ограничения ручного конструктора/вставки в лагере. Проверка повторяет порядок вычислений движка: все распознанные руны влияют на стоимость, затем индексы рун сортируются, а `ic`/`it` ищутся только среди первых восьми.

## Безопасный план развития

1. **Фундамент и полный каталог — выполнено.** Разбор RES/TLV, тёмный интерфейс, восемь БД/26 таблиц, поиск, виртуализация, валидация и чтение исходника без записи.
2. **Полное редактирование — выполнено.** Все физические поля 26 таблиц доступны для записи; Undo/Redo и возврат к оригиналу восстанавливают исходные байты, а не только отображаемый текст. Новая строка создаётся независимым клоном выбранной записи и добавляется только в конец таблицы.
3. **Полное read-only отображение — выполнено.** Все 26 таблиц и 87 924 поля типизированы; legacy-конфликты проверены по исходникам движка, обе реальные базы проходят no-op round-trip побайтово.
4. **Семантические проверки — расширенный этап выполнен.** Добавлены обязательные и уникальные технические ключи, подтверждённые ссылки между материалами, предметами, перками, расами, зонами попадания, заклинаниями и шаблонами, allowlist-проверки enum/диапазонов/списков/масок и аудит вложенной магии оружия/доспехов. Legacy-sentinel учитываются явно; предупреждения ничего не исправляют, а сохранение блокируют только пустые или повторяющиеся ключи новых строк.
5. **Сравнение и пакетные операции — безопасный этап выполнен.** Точные payload-отличия можно выбирать в отчёте, сохранять как версионированный план и применять к модели одной обратимой операцией. Перенос новых/удалённых записей остаётся отдельным будущим этапом.
6. **Установка в игру — отдельная будущая функция.** Она не входит в Preview и может появиться только как явно подтверждаемая операция с резервной копией, проверкой целевого мода и журналом действий.

Preview 71: некорректная дата звукового RES не блокирует чтение базы и звука. Изменение звукового архива с неизвестной датой остаётся заблокированным; каталог RES для чтения не преобразует неиспользуемую дату файловой системы.

Preview 72: отдельная кнопка «Удалить папку…» в дереве RES удаляет её содержимое рекурсивно одним отменяемым действием после подтверждения. Корень защищён; поиск не ограничивает состав удаления.

Preview 73: поиск в связанных текстах и звуках выбранной записи; ▶ в строке звука и «Стоп». Фильтры работают в закреплённой и отделённой панели; распознавание речи не выполняется.

Preview 74: подпись связанного звука содержит ключ из вложенного поля 4 той же реплики acks; поиск учитывает ключ. Имя файла не используется как замена ключа.

Preview 75: поиск связанных текстов и звуков очищается при смене выбранной записи, чтобы запрос предыдущего персонажа не скрывал новые реплики.

### Preview 76: пакетная конвертация MMP

В файловом менеджере RES доступна кнопка «Конвертировать MMP…»: выбранные MMP
или все MMP архива. Автоматический режим анализирует alpha каждого изображения:
DXT1 для непрозрачности/вырезов, DXT5 для плавной прозрачности. Доступны DXT3,
DXT5, DXT1 с пропуском полупрозрачных и отдельное явное упрощение alpha до порога50%.
Размер и имена сохраняются; все mip-уровни формируются до1×1 с минимумом одного
DXT-блока. PNT3 распаковывается существующим декодером, premultiplied RGB переводится
в straight alpha; усреднение mip учитывает alpha, RGB продолжается под прозрачный край.
Вертикального переворота нет. DXT — сжатие с потерями; мелкие детали и cutout-alpha
на дальних mip могут отличаться от исходника.

Вывод: новая папка с converted.res либо подпапкой MMP; report.json содержит результаты
по каждому ресурсу. Повреждённые/неподдерживаемые пропускаются с причиной. Отмена удаляет
временный результат; окончательная папка появляется только после завершения экспорта.
Исходный RES открыт для чтения, проверяется SHA-256, не перезаписывается. Перед
конвертацией сохраните или отмените подготовленные изменения файлового менеджера.

Компрессор Microsoft DirectXTex/texconv may2026 поставляется с редактором (Windows x64,
MIT; third-party/DirectXTex/LICENSE и PROVENANCE.txt). Терминал не нужен.
Выход содержит настоящий 76-байтовый заголовок MMP и DXT mip-данные; DDS используется
только как временный обменный формат с компрессором.

PNT3 может быть слоем: операция не собирает материал доспеха, не меняет модель/UV
и не доказывает совместимость с игровым загрузчиком. Подключение RES и проверка
объектов/рычагов выполняются отдельно; редактор не меняет игру и карты.

### Preview 77: map-имена и открытый RES

По новому требованию результат всегда получает `map` перед `.mmp`:
`unhumadg_03.br.1.x2.mmp` → `unhumadg_03.br.1.x2map.mmp`.
Это относится к новому RES, папке и новому режиму «Добавить в открытый RES».
Существующий map-ресурс не заменяется; входные map.mmp пропускаются с пояснением,
чтобы повторный пакет не создавал mapmap. Оригинальные ресурсы сохраняются.

В режиме открытого RES результат появляется как одна отменяемая операция добавления.
Закройте окно конвертации и нажмите «Перезаписать текущий RES…» для штатного
сохранения с резервной копией либо сохраните копию. До сохранения архив на диске
не меняется. Undo/Redo работают; временные MMP хранятся до закрытия менеджера.
Для объекта имя новой текстуры задаётся без расширения: `unhumadg_03.br.1.x2map`.
Если выбранный архив уже подключён, отдельный новый RES подключать не нужно.
Игровая проверка остаётся отдельной; UV и композиция доспехов не изменены.

Preview78: отдельный явный формат Map x2 (MmpDxtChoice.MapAtlasX2). RepeatAtlasX2
побайтно повторяет исходный BGRA2×2, сохраняя premultiplied flag, затем общий
конвертер выполняет unpremultiply/alpha threshold128/DXT1/mips. Без автоопределения
по имени. Контроль512²→1024²/11mip. Имяmap и существующие варианты вывода сохранены.

Preview79: добавлены явные CompactX2 (512→256→атлас512) и CompactAtlas512
(готовый1024→512 без повторения). Порог альфы0–255, по умолчанию128.
Area-filter учитывает premultiplied alpha; mip-цепочка строится до квантования
альфы каждого уровня. Итог DXT1/512²/10mip. Готовыйmap экспортируется с тем же
именем в новый RES/папку, сохраняя источник. Автоопределение раскладки отсутствует.

Preview80: одиночные структурные поля поддерживают «Очистить слот». Очистка готовит пустую строку, применяется штатной записью поля после подтверждения; обычные списки по-прежнему запрещают пустые элементы.

Preview81: при подтверждении сохранения базы/RES доступен явный пункт «Сохранить без бэкапа». По умолчанию выключен. Временный rollback сохраняет транзакционную защиту, после успеха удаляется; прежние bak не очищаются этим режимом. Связанная пара откатывает texts при сбоеDB.

Preview82: для оружия и брони к связанным текстам добавлен INSTR по имени формы — название и описание чертежа. Связи готовых предметов WEAPON/ARMOR по материалам сохраняются.

Preview83: менеджерRES ограничивает стартовый размер рабочей областью монитора, обрабатывает максимизацию и имеет minimize/restore. Действия сохранения отделены от статуса; компактные боковые панели на узком экране.

Preview84: кнопка последней успешно открытой БД и отдельное запоминание папкиRES для обоих диалогов открытия; настройки сохраняются между запусками.

Preview98: вкладка «Модель» поддерживает все шесть разделов предметов: материалы,
оружие (включая щиты и двуручные классы), броню (все семь слотов), быстрые,
квестовые предметы и лут. Используются инвентарные FIG/MOD из подключённых
архивов figures; формы оружия/брони и быстрые предметы позволяют выбрать
совместимый материал. Начальный материал выбирается с доступной текстурой.
Общие записи чертежей, материала, руны и контейнера заклинания позволяют выбрать
конкретное содержимое; выбор относится только к предпросмотру и не меняет БД.
HD-слой помещается в инвентарный атлас с сохранением исходных UV, ориентации
и premultiplied alpha. Имя суффикса x2/x4 не используется как коэффициент размера:
логический размер берётся из базового MMP, при его отсутствии — из вида предмета
с явным сообщением. Инвентарная модель отличается от вещи на персонаже/карте.
Отсутствующая геометрия или точная текстура сообщаются явно; похожие ресурсы
и иконки вместо геометрии автоматически не подставляются. Анимации и игровая
эквивалентность не заявлены. Кнопки вращения/масштаба и отдельное окно общие
с предпросмотром персонажей. Полный частный аудит: DBE-ITEM-MODEL-001.

## Редактор анимаций — версия 123

Модель справа, шкала кадров и проигрывание под ней. Щелчок выбирает кадр,
Shift + перетаскивание — диапазон; доступны копирование, вставка, дублирование
и удаление. Сглаживание распространяет правку на 0–120 соседних кадров.
Зеркалирование меняет местами парные дорожки и отражает повороты относительно X.
Для распознанных цепочек рук/ног доступны ограничения сгиба и фиксация стоп;
недостижимое перемещение отклоняется целиком, включая предпросмотр жеста.
Оригинал можно показать отдельно или полупрозрачным голубым призраком.

Проект `.eianim` сохраняет ANM, историю Undo/Redo и настройки редактора.
Он привязан к исходному ANM, модели и скелету. Экспорт нового ANM остаётся
отдельной операцией. Проект не устанавливает данные в игру и не меняет ADB.
Ограничения суставов консервативные, не заменяют анатомическую модель;
необычным скелетам не назначаются неподтверждённые цепочки IK.

## Версия 204: общий F5 и связанные ресурсы

«Проверка» по F5 дополнительно проверяет связанные модели/FIG/MMP теми же
resolver/decoder и валидатором, что использует предпросмотр. На странице видны
прогресс, отмена и охват: записи, отдельные ссылки/варианты, уникальные ресурсы,
пропуски и информационные примеры предпросмотра. Запасная экипировка проверяется
по отдельным записанным ссылкам, без перебора всех сочетаний. Материальные
варианты предметов берутся из явных item.material ссылок БД; начальный пример
без такой ссылки проверяется информационно и не считается ошибкой ресурса игры.
Неподдержанная схема отдельно обозначается как непроверенная. Структурные
проверки сохраняются; ресурсные замечания не блокируют сохранение БД.

После правки ячейки выполняется быстрая структурная проверка, ресурсный результат
помечается устаревшим и требует F5. Новый проход, смена БД и отмена не публикуют
старый результат; изменение источников в ходе сканирования отклоняет итог.
Нулевые ошибки не подтверждают здоровье непроверенных вариантов, MOB/save
внешностей, ANM/ADB, эффектов и несвязанных ресурсов или совпадение с игрой.
Контур и границы: docs/testing/database-editor-204-global-resources-20261001.md.

### Версия 205: выбор конвертации оружия
В окне конвертации остаются два режима: «Оружие: Исходное качество для маппера» (MapAtlasX2) и «Оружие: оптимизированное качество для маппера» (CompactX2, выбран по умолчанию). ### Версия 206: поиск формы оружия и брони
Над списком форм — компактный поиск по части русского названия, технического имени или кода модели (например, `initweta1.mod`, `daxe01`, `initarsh`). Поиск учитывает названия для всех совместимых материалов, регистр, `ё`/`е` и несколько слов в любом порядке. Он работает вместе с фильтром типов брони. Ввод не меняет выбранную форму, материал и экипировку: текущая форма остаётся в списке отдельно, если не соответствует запросу; число совпадений и пустой результат показаны под списком. Кнопка × очищает запрос; стрелка вниз/Enter из поиска открывает список. Подсказка формы показывает коды моделей, рассчитанные по параметрам БД; это не проверка наличия ресурсов.
### Версия 207: поиск внутри раскрытого списка формы
Поле поиска перенесено внутрь раскрывающегося списка формы оружия и брони. Оно закреплено сверху над результатами и получает фокус при открытии; список остаётся открыт при вводе. Стрелка вниз переводит фокус на первое совпадение, Enter выбирает его, Escape закрывает только список. Кнопка × очищает запрос и возвращает фокус; повторное открытие сохраняет запрос. Ввод не меняет экипировку. Поиск по RU, форме, моделям и фильтры типов брони сохранены. Проверки и границы: docs/testing/database-editor-equipment-popup-search-207-20261008.md.

### PAK resources (revision 211)

The editor reads PAK 1.1 and retains RES readers for shared base archives and nested MOD/BON/ANM containers. Logical configured `.res` names resolve to mod `.pak` siblings; sibling RES archives are excluded. Mod-root loose resources precede PAK. Figure lookup uses figures then menus; texture lookup uses textures, redress, then menus within PAK/RES tiers, followed by the corresponding base chain. Tombstones stop lower fallback.

PAK serialization and publication use the pinned `EIRebuild64Pack.exe` from PAKTXN01 (commit d6611cf, SHA-256 `0bf903e62c1984d5afe6c51bbb0642836c745540966037a4e44b621d57126f65`). Stale editor snapshots are rejected under native writer locks. Database/text/audio, ANM/ADB and Malachite loose-document changes share one mixed transaction and recovery manifest. Existing PAK images and backups are published as verified exact images, preserving tombstones.

Build the application or UiSmoke project with `-p:PakToolPath=<reviewed executable>` until that dependency is accepted into `builds/rebuild64/current`. The build checks the utility hash, copies its licenses, and keeps the accepted module SDK identities because the public contracts did not change. Malachite PAKMAL01 fixes two missing help entries that otherwise prevented the accepted module from creating its view.

Checks: UiSmoke `--pak <database.res> <new offline directory>` covers resource priority, paired edits, conflict rejection, tombstones, exact restore, mixed recovery and legacy RES. `--module-integration <database.pak> <module package>` opens a local copy and exercises the real hidden host, combined PAK/module SaveAll, Undo/Redo and recovery. Neither command writes to the source game database.
