# Аудит RES/PAK и производительности — 215

Поручение: проверить Редактор БД и Малахит, исправить оставшиеся обращения к
внешним RES вместо PAK и проверить производительность. Связанный модуль —
MALPAKAUDIT01. Основные комплекты и игровые ресурсы при подготовке не изменяются.

## Область и классификация ссылок

Поиск охватил рабочие C#/XAML, хостовые контракты/службы, файловые диалоги,
сборку/упаковку и тестовые входы обоих репозиториев. Проверены цепочки открытия,
сохранения/копии/восстановления БД и текстов, звука, MMP/эффектов, FIG/MOD/BON,
ANM/ADB, каталога объектов, конфигурации, недавних файлов и снимков Малахита.

- Внешние архивы: PAK читается нативно, сохраняется штатной транзакцией упаковщика;
  RES остаётся явно поддерживаемым входным форматом. При автоматическом разрешении
  конфигурации PAK имеет приоритет, но явно выбранный существующий RES сохраняется.
- Ключи `database.res`, `textures.res`, `figures.res` и другие в секции RES —
  логические группы движка. Их переименование в конфигурации неверно.
- MOD/BON/ANM используют внутренние RES-контейнеры. ResArchiveDocument/Writer
  и их сигнатуры для вложенных данных остаются необходимыми.
- Синтетический `texts.res` в идентичности text-only брифингов, адресах Undo и
  старых данных recovery — внутренний ключ, не открытие физического файла.
- Малахит не открывает RES/PAK самостоятельно: он получает неизменяемые записи
  и тексты через SDK хоста. MOB остаётся самостоятельным форматом карты.
- Исторические примеры, старые отчёты, тестовые RES-fixtures не переписывались
  механически. Диалоги подключения/сравнения и сообщения актуализированы.

## Исправления

1. Статическое чтение одного ресурса, звук, ADB, каталог объектов и глобальный
   ANM-индекс больше не создают снимок целого внешнего PAK. Read guard удерживает
   источник на время чтения; нативные проверки таблицы/payload сохранены.
   Редактируемые снимки, контрольные SHA и транзакционная запись сохранены.
2. Пакетный MMP читает под одним проверенным handle; хеширование/чтение выполняются
   в worker. Эффекты используют индекс имён, а не полное декодирование всех MMP.
3. Глобальный поиск ANM/ADB использует группы профиля и Base, loose приоритет и
   tombstones. Один индекс переиспользуется по списку/размеру/FILETIME/config hash;
   изменения источников, добавление loose и ошибки индекса не закрепляют старый кэш.
4. Проверка известных архивов файлового менеджера учитывает PAK и расширение;
   неверный DB payload отклоняется до замены. Копия и резервная копия проверены.
5. Снимок SDK кэшируется до изменения БД/текстов, смены БД и Undo. Скриптовая
   транзакция меняет stamp/dirty, но сохраняет неизменяемый массив записей БД.
   Нумерация повторяющихся полей вычисляется одним проходом вместо квадратичного.
6. Малахит индексирует точные имена квестов/ключи текста по неизменяемому массиву
   записей. Weak-key кэш не удерживает старую БД; зоны/регистр/неоднозначность сохранены.

## Замеры

Один ПК, локальные установленные PAK, отдельные процессы принятой 214 и кандидата.
Это наблюдения конкретных прогонов, не гарантированные верхние границы.

| Сценарий | 214 | 215 |
|---|---:|---:|
| Каталог 1533 моделей | 1.136 с | 0.067 с |
| Короткий звук, первый / повторный | 0.448 / 0.465 с | 0.007 / 0.005 с |
| 10 повторных снимков БД | 1.903 с | 0.0012 с |
| Первый общий индекс анимаций | 3.940 с, 2984 клипа | 0.335 с, 3316 клипов |
| 10000 точных запросов квеста, 3787 записей | 368 мс | 17 мс |
| 40 правок реального скрипта, 265018 символов | 602 мс суммарно | 341 мс суммарно |
| Выделения UI-потока за эти правки | 471.5 МБ | 195.1 МБ |

Повтор ANM-индекса занимает около 11 мс, включая проверку источников; старый
постоянный кэш такую проверку не делал. Ввод большого скрипта всё ещё имеет
пики до 124 мс. Фоновый анализ этого скрипта догнал текст за 2.07 с, с 81 тиком
UI-таймера; ускорение самого анализатора не заявляется. Синтетические 8000 строк
также проверены, но время отдельных нажатий зависит от layout/GC.

## Проверки и ограничения

- Release x64, 0 ошибок/предупреждений; актуальные SDK сохранены.
- PAK-only UI открытия, миграция recent, явный RES с соседним PAK, CRUD/extract/
  copy/in-place, проверка утилиты; исходные игровые SHA не изменились.
- Native: CP1251, пустые ресурсы, prefix/concurrency, повреждение таблицы/payload,
  cancellation, tombstones; шесть texture-regression групп.
- БД/тексты/звук, ANM+ADB и MOB транзакции на копиях, backup/restore,
  stale-group rejection, recovery, совместное владение архивом и RES-regression.
- Снимки: DB edit, Undo, смена БД, скриптовая ревизия, блокировка смены БД при
  несохранённом документе; база не менялась при тестах чтения/ввода.
- Реальный WPF хост + независимый пакет Малахита: большой MOB, ввод, фоновый анализ,
  Undo/Redo; PAK-fixture Maps, обычное сохранение/копия и переиндексация изменённой карты.
- 151 установленный MOB: первый индекс 7.819 с, повтор 0.925 с; 151 cached result,
  52.7 МБ кэша. Пять карт без пригодного скриптового чанка пропущены с диагностикой.
- Четыре ADB (`inmm1`, `unmoco3`, `unmoco4`, `unmozozo`) имеют размер меньше
  `44 + count*88`, принятого текущим парсером. У трёх размер соответствует 84-байтным
  записям. Их формат/данные не преобразованы по догадке; это отдельная находка.
- Старый общий Malachite.Module.Verification не собирается из-за ссылки на удалённый
  `QuestStudio.TextChange`. Актуальные проверки вынесены в Malachite.PakAudit и
  существующий HostIntegration; устаревшие проверки удалённых карточек не объявляются
  пройденными. Старое standalone-окно не является поставляемым модулем; его UI здесь
  не проверялся. Игровой прогон и все возможные внешние наборы архивов не проверялись.

Полные журналы/снимки/fixtures находятся только в заданиях. Для повторения:
UiSmoke `--pak-audit215`, `--pak-audit215-checks`, `--animation-index215`,
`--pak-opening`, `--pak`, `--textures`, `--pak-native`; Malachite.PakAudit и
HostIntegration `editor-only`/`maps-only`. Пакеты с PDB проходят полный SHA256SUMS.
