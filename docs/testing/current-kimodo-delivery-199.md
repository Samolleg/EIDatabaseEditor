# Совместное обновление редактора и Kimodo

`tools/Publish-Current.ps1 -PackagePath <проверенный комплект>` проверяет
`host-manifest.sha256.json` и, при наличии в комплекте,
`Kimodo/install-manifest.json` формата `kimodo-editor-install-v1`.
Пути проверяются внутри соответствующего каталога. Размеры и SHA-256 всех
входящих файлов проверяются до записи; изменённый пользователем установленный
файл не перезаписывается. Редактор и Kimodo из current должны быть закрыты.

Манифесты остаются раздельными. Обновление только хоста не удаляет Kimodo.
Неизменённые веса и другие файлы не копируются; пользовательские файлы вне
манифестов сохраняются. Файлы старого Kimodo, отсутствующие в новом манифесте,
автоматически не удаляются. Модуль Малахита по-прежнему обслуживается своим
процессом обновления; изменение установленного модуля относительно пакета
будет обнаружено штатной проверкой конфликта.

Перед записью заменяемые файлы сохраняются в проверенную временную папку
`database-editor-rollback-*`, путь выводится скриптом. Состояние назначения
сверяется повторно. Если копирование или проверка результата не удались,
скрипт восстанавливает уже затронутые файлы и сообщает об ошибках отката.
Это защита от ошибок операции, а не гарантия восстановления при отключении
питания или завершении самого процесса PowerShell.

Изолированная проверка: `tools/Test-PublishCurrent.ps1`. Она создаёт маленькие
синтетические пакеты во временном каталоге и проверяет совместное обновление,
повреждённый native-файл, внешнее изменение назначения, отказ в середине
копирования с откатом, сохранность пользовательских данных/весов/модуля и
последующее обновление только хоста. Реальный current тест не изменяет.

Кандидат приложения 199 R2 и его DLL не пересобирались из-за изменения
PowerShell-процедуры. Их проверки и ограничения описаны в
`work/investigations/dbe-kimodo-constraints-20260930/REPORT-R2.md`.
