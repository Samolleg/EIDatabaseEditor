# Kinematic Constraints Config — рабочая схема v1

В форме Kimodo раскройте **Kinematic Constraints Config (JSON)**. Поле принимает
только декларативный JSON: неизвестные и повторные поля, произвольные названия
поз, кадры вне длины клипа и неконечные значения отвергаются до инференса.
Ограничения скорости корня и общего радиуса конечности служат грубой
отсечкой; реальная достижимость игровой цепи проверяется при импорте до
принятия ANM. JSON не исполняется и не добавляется к текстовому
запросу. Для непустого конфига нужен генератор с `--capabilities` =
`spatial-v1`; старый исполняемый файл отвергается до создания истории.

Все координаты здесь — **метры, Kimodo Y вверх**, X/Z — плоскость земли,
номер кадра начинается с 0. Для 90 кадров последний допустимый номер — 89.
Корень в кадре 0 должен быть `(0, 0)`. Параметры
`text_guidance` и `constraint_guidance` — отдельные веса CFG (по умолчанию 2),
допустимы соответственно 0–10 и (0, 10]. `seed = 0` в обычной форме остаётся
случайным; фактический seed пишется в историю.

## Траектория корня

```json
{
  "version": 1,
  "space": "kimodo_y_up_meters",
  "text_guidance": 2,
  "constraint_guidance": 2,
  "root2d": [
    {"frame": 0, "x": 0, "z": 0},
    {"frame": 45, "x": 0, "z": 0.5},
    {"frame": 89, "x": 0.2, "z": 1}
  ]
}
```

`root2d` воздействует на нормализованные признаки сглаженного корня во время
каждого шага денойзинга. После импорта редактор плавно совмещает игровую
траекторию с указанными точками. Выберите в форме «Одно действие с перемещением»: режим «Повтор на
месте» переписывает траекторию при закрытии цикла и для JSON отвергается.
Кнопка «Проверить» показывает точки корня сверху (X вправо, Z вверх).

## Кисть или стопа

```json
{
  "version": 1,
  "space": "kimodo_y_up_meters",
  "root2d": [
    {"frame": 0, "x": 0, "z": 0},
    {"frame": 30, "x": 0, "z": 0}
  ],
  "effectors": [
    {"frame": 30, "joint": "left_hand", "position": [0.25, 1.1, 0.3]}
  ]
}
```

Поддержаны точные имена `left_hand`, `right_hand`, `left_foot`, `right_foot`.
Для каждого целевого кадра конечности требуется `root2d` в том же кадре.
Редактор переводит мировую позицию в признак сустава относительно
сглаженного корня и маскирует его в native sampler. После переноса игровая
трёхзвенная цепь доводит кисть или стопу IK до целевой точки; недостижимая
цель отвергает импорт целиком и сохраняет исходные потоки в истории.
Цель одного сустава не
задаёт ориентацию кисти, форму хвата, контакт пальцев, пятки/носка или
совместный объект в двух руках. Двуручный хват требует отдельной модели
предмета/solver и здесь не заявлен.

## Поза из открытого клипа

Кнопка «Поза текущего кадра» добавляет:

```json
{
  "version": 1,
  "space": "kimodo_y_up_meters",
  "key_poses": [
    {"frame": 0, "source_clip": "cidle09", "source_frame": 0}
  ]
}
```

`source_clip` должен существовать в текущем черновике ANM и иметь проверенную
гуманоидную иерархию. Кнопка читает текущие несохранённые правки. Редактор
снимает мировые позиции 15 игровых узлов, определяет плоскость подошв по
исходному клипу покоя и геометрии стоп, переводит оси Z-вверх → Y-вверх,
нормирует масштаб длиной ног и отправляет
позиционные цели соответствующих 15 узлов SOMA30. Не представленные игрой
15 узлов SOMA30 остаются свободными. После импорта IK доводит целевые кисти
и стопы; остальные узлы остаются приближёнными. Поза не восстанавливает
исходные локальные вращения SOMA30 и не обеспечивает точную обратимость.
Высота цели равна `(game Z − исходная плоскость подошв) / scale`. При переносе
обратно игровая плоскость намеренно нормирована к `Z = 0`: `game Z = target Y × scale`.
Это сохраняет высоту **относительно подошв**, а не исходное абсолютное смещение
ANM в мире. Для открытого черновика опорная плоскость берётся из неизменного
исходного idle, поэтому поднятие одной анимированной стопы не сдвигает весь пол.
После импорта проверьте игровой вид, опоры и переходы.

## История и порядок применения

`generation.json` сохраняет исходный JSON, разрешённые native цели,
параметры, фактический seed, SHA-256 генератора и весов. Отдельно сохраняются
`constraints.json`, `spatial-targets.txt`, исходные потоки
`root_positions.f32`, `local_rotations_xyzw.f32` и, если новый генератор её
выдал, `joint_positions.f32`; хэши проверяются при replay. Повторный импорт
использует исходные потоки без нового инференса. После генерации редактор
переносит движение на игровой скелет, корректирует высоту стоп, совмещает
точки корня и доводит достижимые кисти/стопы IK; эти этапы отличаются от
conditioning. Для JSON не применяется старое точное приведение
первого/последнего кадров к idle, так как оно перезаписало бы заданные цели.
Заполненный JSON отключает выбор опорного клипа покоя в форме. Для точного
перехода idle оставьте JSON пустым; совместное требование idle и JSON пока
не поддержано.

Официальная [схема ограничений Kimodo](https://research.nvidia.com/labs/sil/projects/kimodo/docs/user_guide/constraints.html)
описывает более широкий Python/CLI API. Этот локальный JSON — отдельная
версионированная схема редактора с доказанным `root2d` и позиционными
признаками суставов. Foot-contact conditioning и полный fullbody inverse-rig
здесь не поддерживаются.
